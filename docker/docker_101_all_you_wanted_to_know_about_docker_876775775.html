First and foremost, what is Docker? 🧐

Docker is an open-source containerization tool mainly used for shipping and running applications quickly across different platforms. Docker’s way of shipping and deploying code swiftly, significantly reduces the delay between writing code and running it in production. It is developed using GO and was first released in 2013.

Why Docker?

Docker has a list of advantages that makes it super useful. Some of them are:

  1. Isolation

It helps us create an environment agnostic system. Your application runs smoothly on different platforms. This is essentially achieved using containers.

2. Portability

Since all of your dependencies are in the same container, it’s easy to carry from one place to another giving Docker its portability.

3. Lightweight

Runs as another application on your system instead of consuming whole lot resources of your system.

4. Robustness

Less demanding in terms of hardware and needs very little memory as compared to VMs, hence providing efficient isolation levels which help save not only the cost but also time.

Before we dive in further, why do we need Docker at all? Don’t we have enough tools around, huh?🤨

Yes, we do. Loads of them, but Docker is different. It makes our life easier. I’ll tell you how — Keep reading.

Allow me to give you some background!

Background

Once upon a time, we used to install software on OS which was installed on a specific set of hardware- CPU, Memory, and disk. Let’s fast forward a bit, there comes the age of virtualization. Running multiple OSs within the same OS allowing some level of hardware isolation. For instance — running Ubuntu on Windows using VirtualBox.

This is pretty cool you see but in the era of Agile, where time is money and you need to deliver continuously and present deliverables at the end of each sprint, chasing IT departments like operation to get access for different development environments for different stories (e.g. resource-intensive processes that need more memory/disk) can be daunting as well as time-consuming.

Worry no more, Here comes Docker to the rescue. It has something for you, a product that goes by the name docker which provides not only a lightweight level of virtualization but also an open-source Linux based software that can run on any hardware that supports docker instances like Windows or OSX. Docker achieves this level of virtualization by using containers. It’s a metaphor really as it works the same way a normal container does. It does store things in it.

A container is a standard unit of software that bundles up code and all its dependencies so the application runs smoothly and swiftly irrespective of the computing environment. Honestly, a container is nothing but a running process, with some added encapsulation features applied to it to keep it isolated from the host and other containers. [1]

Lightweight, you said?

Docker containers run as executable and unlike virtualization which takes up a significant portion of system resources, a container is just like another executable application that provides a similar level of virtualization but in a resource-efficient and more secure way. Since Docker containers share the same system resources, this makes them efficient. For example — a system where one needs to run virtual machines, one can have different Docker containers and have some level of isolation which you usually have in your VMs.

One of the most important aspects of container isolation is that each container interacts with its private filesystem; this filesystem is provided by a Docker image. This essentially means the need for fewer resources and in turn cost.

Cool, what’s an image?

It’s not what you think it is. It is more like a photocopier. You can make your containers from an image just like you can photocopy using the Xerox machine. It is nothing but a template that contains an application, as well as all the dependencies, needs to run your application like your code, libraries, config files, environment variables (ex- PATH), etc. This image can be deployed to different environments. Wondering how an image is different from the container? Well, a container is a running instance of an image.

Now that we know a bit about Docker, Let’s have a look at its architecture.

Client-Server Architecture

The Docker command line uses the Docker REST API to interact with the Docker daemon. Docker client is the command-line tool and that’s how users interact with Docker. Docker daemon listens to ports for Docker client API requests and manages Docker objects such as images and containers. The client and server can be on the same machine. A Registry is where docker images are stored. It is a public registry and by default, images are stored on Docker hub. You can use the Registry of your choice for storing images.

Docker Hub

It is an official online repository where all docker images are stored and it also permits those images to be distributed. As discussed above, Docker uses Linux based CLI tool to interact with Docker Daemon. You can use this CLI to create and publish your image to Docker Hub. There are two ways to achieve this –

1. Create an image locally and push it to Docker Hub.

2. Create a docker file and use Docker continuous build system to build images. (Preferred)

Before you can push the image to Docker hub, you need an account (The basic version is free, get yours here) and Docker hub Desktop application. The pre-requisite for this is that you should have Docker installed on your system (Get Docker CE(Community Edition)). After you authenticate yourself, you can start pushing your images to the docker hub.

Who needs Docker?

You may want to use Docker if you need quick and consistent delivery of your application. Predominantly, Software Engineers, DevOps Engineers, Data Engineers, and Data Scientists can benefit from Docker. Docker streamlines the software development lifecycle by allowing developers to work in standardized environments that work like a charm for continuous integration and continuous delivery (CI/CD) workflows.
