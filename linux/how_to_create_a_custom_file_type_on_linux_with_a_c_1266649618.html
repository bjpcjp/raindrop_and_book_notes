1. Create a Custom MIME Type

Linux relies on MIME types to associate file extensions with content types. We’ll create a new one: application/x-maso.

We use the MIME type application/x-maso to associate our custom .maso file format with the system. The application/ prefix indicates that the file contains binary or non-text data, while the x- prefix is a common convention in Linux systems for unofficial or custom formats that are not registered with IANA (the organization that manages official MIME types). This avoids potential conflicts with future standardized types and follows the same pattern used by many well-known formats like application/x-tar or application/x-deb. If the .maso format were to become widely adopted and officially registered, we could eventually drop the x- prefix.

📄 File: ~/.local/share/mime/packages/maso.xml

<?xml version="1.0" encoding="UTF-8"?>
<mime-info xmlns="http://www.freedesktop.org/standards/shared-mime-info">
  <mime-type type="application/x-maso">
    <comment>MASO File</comment>
    <glob pattern="*.maso"/>
    <icon name="application-x-maso"/>
  </mime-type>
</mime-info>

Then update the MIME database:

update-mime-database ~/.local/share/mime

🔍 Why? This tells the system how to recognize .maso files by their extension and treat them as a distinct file type.

2. Associate Your App with the MIME Type

Next, we need to register our app as a handler for .maso files.

📄 File: ~/.local/share/applications/maso.desktop

[Desktop Entry]
Name=MASO
Comment=Multi-platform application for learning operating systems
Exec=/full/path/to/your/flutter/app %f
Icon=application-x-maso
Terminal=false
Type=Application
MimeType=application/x-maso
Categories=Education

Then update the MIME associations:

xdg-mime default maso.desktop application/x-maso

🔍 Why? This links your MIME type to your Flutter executable so Linux knows what app to launch when you double-click a .maso file.

3. Add a Custom Icon

To give your file type a visual identity, place your icon(s) in the appropriate icon theme folder. I recommend adding it to all folders so that it is appropriate on all types of screens.

📁 Target folder: ~/.local/share/icons/hicolor/[size]/mimetypes/

For example:

mkdir -p ~/.local/share/icons/hicolor/64x64/mimetypes/
cp application-x-maso.png ~/.local/share/icons/hicolor/64x64/mimetypes/

Make sure the file name matches the icon name declared in both your MIME and .desktop file:
application-x-maso.png

Then rebuild the icon cache:

gtk-update-icon-cache ~/.local/share/icons/hicolor

🔍 Why? GTK and desktop environments use icon caches to quickly find the right icon for MIME types.
